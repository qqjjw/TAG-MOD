# 변덕의 장비와 몬스터 · TagMod

Minecraft Java 26.3의 기본 플레이에 랜덤 몬스터 강화와 한국어 장비 옵션을 추가하는 Fabric 모드입니다. 개인 테스트와 두 사람의 LAN 플레이를 위해 만들었습니다.

**현재 버전: 0.1.2**

## 준비물

| 항목 | 버전 |
|---|---|
| Minecraft Java Edition | 26.3 |
| Fabric Loader | 0.19.5 이상 |
| Fabric API | 26.3용. 개발에 사용한 버전은 0.162.0+26.3 |
| Java | 25 |

## 설치와 LAN 플레이

두 사람 모두 같은 JAR와 설정 파일을 사용합니다.

1. 런처에서 26.3용 Fabric 프로필의 **게임 디렉터리**를 확인합니다. 기본 경로는 `%APPDATA%\.minecraft`이며 별도 지정한 프로필은 해당 폴더를 사용합니다.
2. 게임을 종료하고 게임 디렉터리의 `mods`에 `tagmod-0.1.2.jar`와 26.3용 Fabric API를 넣습니다. 기존 TagMod JAR는 빼고 새 버전 하나만 남깁니다.
3. 제공된 `config/tagmod.json`을 게임 디렉터리의 `config/tagmod.json`으로 복사합니다. 파일이 없으면 첫 월드 시작 시 기본값으로 생성합니다.
4. 한 사람이 월드를 열고 **LAN 서버 열기**를 선택합니다. 다른 사람은 멀티플레이에서 접속합니다.

추첨·능력치·효과 처리는 호스트의 서버에서 수행합니다. 접속자의 로컬 설정으로 재추첨하지 않습니다.

설치 파일은 프로젝트의 `dist/TagMod-0.1.2.zip`과 `dist/TagMod-0.1.2/`에 있습니다. Git에는 배포 파일을 포함하지 않으므로 새로 내려받은 소스에서는 먼저 빌드해야 합니다. Fabric API는 별도로 준비합니다.

### 업데이트와 설정 적용

- **JAR 변경:** 양쪽 게임을 완전히 종료하고 기존 JAR를 교체합니다.
- **확률·수치 변경:** 설정 파일을 수정한 뒤 월드를 나갔다 다시 엽니다. 두 사람은 같은 설정 파일을 사용합니다.
- 기존 설정은 업데이트 시 자동으로 덮어쓰지 않습니다. 새 기본 확률을 사용하려면 제공된 설정을 복사하거나 해당 항목을 편집하세요.
- 이미 처리된 장비·몬스터는 다시 추첨하지 않습니다. 새 확률은 이후 최초 처리되는 대상에 적용됩니다.
- 빌드·패키징 결과는 게임 폴더로 자동 복사하지 않습니다.

## 주요 기능

### 몬스터

| 기능 | 기본 설정 |
|---|---|
| 일반 대상의 포션 강화 | 50% |
| 강화 개체의 특성 수 | 1개 80%, 2개 20% |
| 장비 사용 몹의 추가 무장 | 20% |
| 추가 장비의 기본 드롭률 | 슬롯당 0.5%, 약탈 보정 유지 |
| 일반 대상의 대형화 | 8%, 기본 크기의 1.6~2배 |
| 보스·워든 | 10% 확률로 저항 I, 대형화 제외 |

적대 몬스터와 공격 가능한 중립 몹을 대상으로 합니다. 일반 가축·주민은 제외합니다. 자연 생성뿐 아니라 생성기·생성 알·명령어 및 기존 월드에서 최초 처리되는 대상에도 적용합니다.

효과 후보는 신속 I·저항 I·점프 강화 I·힘 I·화염 저항·간헐적 투명화입니다. 몹의 공격 방식에 맞춰 후보를 제한하며 파티클을 표시합니다. 투명화는 전투 여부와 관계없이 20~40초 간격으로 2초간 발동합니다. 보스의 저항 I 외에는 기존 효과 면역을 유지합니다.

추가 무장은 가죽·사슬·철 중심으로 빈 방어구 슬롯 1~2개를 채우고 일부 비무장 좀비류에는 검을 줍니다. 기존 활·쇠뇌는 유지합니다. 낮춘 드롭률은 **모드가 추가한 장비**에만 적용합니다.

대형화는 포션·추가 무장과 독립적으로 추첨합니다. 외형과 충돌 크기가 함께 바뀌며 체력·피해량은 별도로 증가시키지 않습니다. 이름표나 디스폰 방지 상태는 새로 설정하지 않습니다.

### 장비

- 근접·원거리 무기, 채굴 도구, 방어구, 방패, 겉날개, 낚싯대, 가위, 부싯돌과 부시, 솔에 한국어 접두사와 옵션 1~3개를 부여합니다.
- 유리·불리·혼합 유형의 기본 비중은 같습니다. 혼합 유형은 옵션 2~3개에 장단점을 모두 포함합니다.
- 피해량·공격속도·사거리·내구도·채굴·장전·방어·이동·낙하·수중 능력과 약한 흡혈, 장착 중 1레벨 포션 효과 등을 장비 종류에 맞게 추첨합니다.
- 부정 포션 후보에는 독·위더·실명·어둠·공중 부양도 있습니다. 같은 포션 효과를 여러 장비로 받아도 레벨은 합산하지 않습니다. 외부 포션·비콘 효과를 우선합니다.
- 방어구·겉날개는 착용 슬롯, 방패는 어느 손에서든, 나머지는 주손에서 효과가 켜집니다. 가방 속 장비에는 장착 효과가 없습니다.
- 흡혈 기본값은 실제 감소한 체력의 3%, 적중당 최대 체력 1포인트, 1초 간격입니다. 직접 근접·투사체 공격에만 적용합니다.
- 제작·거래·전리품·드롭·낚시·명령어·크리에이티브 등에서 획득한 미처리 장비를 처리합니다. 크리에이티브 전체 견본 목록을 일괄 추첨하지 않습니다.
- 일반 제작·거래 견본에는 옵션이 없을 수 있으며 실제로 꺼낼 때 적용합니다. 사용자가 붙인 이름은 보존합니다.

| 작업 | 옵션 처리 |
|---|---|
| 이동·버리기·회수·사망 회수·복사·재접속 | 유지 |
| 재료 수리·두 장비 합성·네더라이트 업그레이드 | 재추첨 |
| 수선·이름 변경·인챈트·숫돌 단독 처리·방어구 장식 | 유지 |

수리·합성 미리보기는 같은 입력에서 고정됩니다. 입력을 넣었다 빼거나 창을 다시 여는 것만으로 재추첨하지 않습니다. 인챈트 제거와 재료·경험치 소비는 해당 바닐라 작업 규칙을 따릅니다.

## 소스에서 빌드하기

Windows PowerShell과 **JDK 25**가 필요합니다. Java 실행 환경만 있는 JRE가 아니라 `java`, `javac`, `jar`가 포함된 JDK를 설치하고 세 명령을 PATH에 등록하세요.

이 프로젝트는 Gradle 대신 PowerShell 스크립트로 직접 컴파일합니다. 설치된 공식 게임 파일을 사용하므로 다음 준비가 필요합니다.

1. Minecraft 런처에서 **26.3**을 한 번 실행해 게임 JAR와 라이브러리를 준비합니다.
2. **Fabric Loader 0.19.5 / Minecraft 26.3** 프로필을 설치합니다. 현재 빌드 스크립트는 이 정확한 프로필 경로를 사용합니다.
3. 빌드에 사용할 `.minecraft` 폴더의 `mods`에 **26.3용 Fabric API JAR**를 넣습니다. 파일 이름은 `fabric-api-*+26.3.jar` 형식이어야 합니다.
4. 저장소를 내려받고 프로젝트 루트에서 빌드 명령을 실행합니다.

```powershell
git clone git@github.com:qqjjw/TAG-MOD.git
cd TAG-MOD

# 컴파일과 JAR 생성만 실행합니다. 테스트·게임 실행은 하지 않습니다.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build.ps1
```

기본 게임 파일 경로는 `%APPDATA%\.minecraft`입니다. 다른 위치에 설치했다면 다음과 같이 지정합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build.ps1 -MinecraftDirectory 'D:\Minecraft'
```

지정한 폴더에는 `versions/26.3`, `versions/fabric-loader-0.19.5-26.3`, `libraries`, Fabric API가 있는 `mods`가 필요합니다. 별도의 플레이 프로필 폴더에는 이러한 공통 게임 파일이 없을 수 있으므로 구분하세요.

### 빌드 결과와 설치용 ZIP

현재 버전의 빌드 결과는 **`build/libs/tagmod-0.1.2.jar`**입니다. 파일명의 버전은 `src/main/resources/fabric.mod.json`에서 읽습니다.

설정과 문서를 포함한 설치용 ZIP을 만들려면 JAR 빌드 후 아래 명령을 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package.ps1
```

결과는 `dist/TagMod-0.1.2.zip`과 `dist/TagMod-0.1.2/`에 생성됩니다. 패키징은 기존 JAR를 사용하며 재컴파일·테스트하지 않습니다. 게임에 적용하려면 [설치와 LAN 플레이](#설치와-lan-플레이) 순서대로 새 JAR와 설정을 직접 복사하세요.

`build`, `dist`, 캐시는 Git에 포함하지 않으며 빌드·패키징 시 다시 생성됩니다. 빌드는 게임 파일이나 의존성을 다운로드하지 않습니다. 테스트는 기본 빌드에 포함되지 않으며, 추가 검사·컴파일·테스트 실행은 사용자와 범위를 합의한 뒤 진행합니다. 검사 옵션과 소스 수정 지점은 [개발 안내](docs/DEVELOPMENT.md)에 정리되어 있습니다.

## 플레이 중 확인과 문제 신고

치트가 허용된 LAN 호스트 또는 명령 권한이 있는 사용자는 다음 명령을 쓸 수 있습니다.

| 명령 | 용도 |
|---|---|
| `/tagmod inspect` | 주손 장비의 저장된 옵션과 추첨 ID 확인 |
| `/tagmod roll` | 주손 장비 무료 재추첨. 테스트 전용 |
| `/tagmod spawn` | 신속·간헐적 투명화 테스트 좀비 생성 |
| `/tagmod mob @e[type=minecraft:zombie,sort=nearest,limit=1]` | 가까운 좀비의 처리·강화 태그 확인 |

플레이를 확인할 때는 장비 획득·교환, 수리 전후 옵션, 장착 효과 해제, 대형 몬스터, 사망 회수·재접속을 살펴보면 됩니다. 확률을 바꾸고 이미 처리된 몹만 관찰하면 변경이 드러나지 않을 수 있습니다.

오류가 발생하면 **실제 게임 디렉터리**의 `logs/latest.log`와 `crash-reports`의 최신 보고서, 모드 버전, 재현 순서를 확인하세요. 장비 문제에는 `/tagmod inspect` 결과가 도움이 됩니다.
